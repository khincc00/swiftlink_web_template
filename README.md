# SwiftLink Logistics & Transport — Website Template

A responsive, multi-page website template for a licensed transport and logistics company in Singapore. It covers goods delivery, corporate charter, point-to-point transfers and warehousing.

- **Plain HTML, CSS and JavaScript.** No framework, no npm, no runtime dependencies.
- **One small build script** (Python 3.8+, standard library only) adds the shared header, footer, SEO tags and icons to every page.
- **Works on any static host:** Netlify, Vercel, GitHub Pages, Cloudflare Pages, cPanel/Apache or Nginx.

> **Template status:** company details, prices, testimonials, tracking records, job openings and photos are **sample data** for design review. Replace them once the design is approved. The [pre-launch checklist](#pre-launch-checklist) lists every item.

## Quick start

```bash
# 1. Preview: open index.html in a browser, or run a local server (recommended)
python3 -m http.server 8000          # then visit http://localhost:8000

# 2. After editing anything in _src/ or _tools/build.py, rebuild the pages
python3 _tools/build.py
```

Use a local server instead of opening the files directly (`file://`) when you test:

- the 404 page, which uses root-relative links;
- form submission to an endpoint;
- the web app manifest.

**Requirements**

| Task | Tool |
|---|---|
| Build pages | Python 3.8 or newer (macOS and most Linux systems include it) |
| Create WebP photos (optional) | `cwebp`: `brew install webp` or `apt install webp` |
| Re-render icons and the social image (optional) | Google Chrome or Chromium |

## How the build works

`_tools/build.py` reads each file in `_src/pages/`. It wraps the file in the shared `<head>`, icon sprite, header, footer and mobile action bar, replaces the placeholders, and writes the finished page to the project root. It also writes `sitemap.xml` and `robots.txt`.

### Page header block

Every source page starts with a settings comment:

```html
<!--
title: Services &amp; Fleet | SwiftLink Logistics &amp; Transport
description: One-sentence summary for search results and share previews.
nav: services
script: quote.js          (optional) extra script from assets/js/
robots: noindex           (optional) hide from search engines and the sitemap
sitemap: no               (optional) leave out of sitemap.xml only
image: assets/images/photos/x.jpg   (optional) per-page share image
rootlinks: yes            (optional) root-relative links, used by 404.html
-->
```

`nav` highlights the matching menu item. Use any other value, such as `privacy`, for pages that aren't in the menu.

### Placeholders

| Placeholder | Output |
|---|---|
| `{{icon:truck}}` | Inline SVG icon from `ICONS` in `build.py`. An unknown name stops the build with an error |
| `{{c:phone}}` | Value from `COMPANY`, e.g. `name`, `phone`, `tel`, `whatsapp`, `email`, `dpo_email`, `address`, `licence`, `uen` |
| `{{s:url}}` | Value from `SITE` |
| `{{sgmap}}` | The interactive map from `_src/sgmap.svg` |

### Adding a page

1. Create `_src/pages/new-page.html` with a header block. Copy the hero from an existing page, such as `careers.html`.
2. If the page belongs in the main menu, add it to `NAV` in `build.py`. Otherwise add it to a `FOOTER_COLUMNS` list.
3. Run `python3 _tools/build.py`. The page is added to the sitemap automatically.

### Adding an icon

Add a 24 × 24 stroke path to `ICONS` in `build.py`. It is then available as `{{icon:name}}` in pages and as `<use href="#i-name">` from JavaScript.

## Features and how to customise them

### Pricing engine

`SL.calc(state)` in `main.js` powers both the hero estimate and the quote wizard:

- **Goods:** trip rate × region distance factor.
- **Charter and transfers:** hourly rate × hours, never below the service minimum.
- **Storage:** pallets × weeks × weekly rate, plus handling in and out.

Surcharges then stack on the base price:

- urgent: +20%;
- after-hours (22:00–07:00): +25%;
- Sunday or public holiday: +15%.

Add-ons are added as flat prices. The visitor sees a range of ±`spread` (12%), rounded to S$5. All figures live in `config.js`.

### Quote wizard (`quote.js`)

- **Steps:** Service → Details → Schedule → Extras → Review. Each step is a `<fieldset class="step" data-step="N">`.
- **Adding a step:** add the fieldset and a step label, then raise `total` in `quote.js`.
- **Skipping step 1:** URL parameters do this, e.g. `quote.html?service=charter&vehicle=coach&hours=4`. The hero estimate, service pages and vehicle matcher all link this way.
- **Public holidays:** dates listed in `publicHolidays` tick and lock the holiday checkbox and add the surcharge.
- **Validation:** step 5 requires name, email, mobile and **PDPA consent**.

### Shipment tracking (`track.js`)

The template reads the demo records in `config.js → shipments`. Try `SL-240918` (in transit), `SL-240917` (delivered) or `SL-240920` (scheduled).

To connect a real dispatch system or TMS, replace **`lookup()`** in `track.js` so it returns a Promise for a record in the same shape:

```js
function lookup(key) {
  return fetch('https://api.example.com/track/' + encodeURIComponent(key))
    .then(function (r) { return r.ok ? r.json() : null; });
}
```

All API text is HTML-escaped before it is displayed. Then remove the "Demo data" note in `renderShipment()` and the sample-number chips in `track.html` and `index.html`.

### Vehicle matcher

The matcher estimates the load volume as:

- cartons: 0.08 m³ each;
- pallets: 1.6 m³ each;
- large items: 0.9 m³ each.

It then recommends the smallest vehicle with enough usable space (85%) and pallet slots. If nothing fits, it suggests several of the largest vehicle. For passengers, it picks the smallest vehicle with enough seats and luggage room. Tune these numbers in `initMatcher()` in `main.js`.

### Coverage map

`_src/sgmap.svg` has one `<path class="map-region" data-region="…">` per region, using the same keys as `config.js → regions`. Hub pin positions and label positions are set in `initMap()`.

### Contact form and careers

- `contact.html?topic=account|booking|feedback|careers` preselects the topic.
- `contact.html?topic=careers&role=Coach+Captain` pre-fills a job application. Every Apply button on `careers.html` uses this link.
- The booking-number field appears only for the booking and feedback topics.

### Other

| Feature | Where to change it |
|---|---|
| **Dispatch status** in the top bar | `config.js → dispatch` (evaluated in Singapore time) |
| **FAQ** search and filters | Copy a `<details class="faq-item" data-cat="…">` in `index.html` |
| **Gallery** | Copy a `<figure class="g-item">`; categories and counts update automatically |
| **Light / dark theme** | Follows the system setting. The toggle choice is carried between pages with `?theme=` (no cookies) |

## Forms and lead capture

By default, both forms open the visitor's email app with the message filled in (`mailto:`). The quote can also be sent by WhatsApp. For reliable lead capture, **connect a form endpoint**:

1. Create a form at Formspree, Web3Forms, Getform or Basin, or build your own endpoint. It must accept a POST with `multipart/form-data` and return a 2xx status.
2. Set the URLs in `config.js`:

   ```js
   forms: {
     contact: 'https://formspree.io/f/xxxxxxx',
     quote:   'https://formspree.io/f/yyyyyyy'
   }
   ```

3. Test both forms on the live domain.

With an endpoint set:

- the quote button changes to **"Send request"**;
- the quote is submitted in the background with all form fields, plus `reference`, `estimate` and a readable `summary`;
- WhatsApp stays available as a second option.

Both forms also include:

- a **required PDPA consent checkbox** linking to `privacy.html`;
- a hidden **honeypot** field (`_gotcha`) that drops spam bots silently;
- inline validation with accessible error messages.

## SEO, sharing and analytics

`build.py` generates the following on every page:

- `<title>`, meta description, **canonical URL** and `theme-color`;
- **Open Graph and Twitter card** tags with absolute URLs, for WhatsApp, LinkedIn, Facebook and X previews;
- **schema.org JSON-LD** (`MovingCompany`) built from `COMPANY` and `SOCIAL`;
- favicon (SVG), `apple-touch-icon.png` and the `site.webmanifest` link.

It also writes:

- `sitemap.xml` with every indexable page; submit it in Google Search Console;
- `robots.txt`, which allows everything except `_src/` and `_tools/` and points to the sitemap.

**Analytics.** Set `SITE["ga4_id"]` and rebuild. `SL.track()` in `main.js` then sends these events:

| Event | When |
|---|---|
| `contact_click` (`method`: phone / whatsapp / email) | Any `tel:`, `wa.me` or `mailto:` link is clicked |
| `generate_lead` (`form`: contact / quote, plus service and value) | A form passes validation and is sent |
| `track_shipment` (`found`: true/false) | A tracking lookup is made |

`SL.track()` also works with Google Tag Manager (`dataLayer`). Mark `generate_lead` as a key event in GA4. If you enable analytics, keep section 10 of the privacy policy as written; without analytics, remove its second paragraph.

## Images and brand assets

### Photos

- Photos are in `assets/images/photos/`. Use landscape images about 1400–2000 px wide.
- Keep the `width` and `height` attributes on every `<img>` to prevent layout shift.
- Use `alt=""` for decorative background images.

**WebP.** Run `bash _tools/optimize-images.sh`, then `python3 _tools/build.py`:

1. The script creates a `.webp` next to each `.jpg`, about 40% smaller.
2. The build then wraps every photo in `<picture>`, so supporting browsers download the WebP.
3. `picture { display: contents }` in the CSS keeps the layout unchanged.

### Icons and social image

| File | Source | Re-render with |
|---|---|---|
| `favicon.svg` | Edit directly | – |
| `apple-touch-icon.png`, `icon-maskable-512.png` | `_src/brand/icon-square.svg` | `bash _tools/render-brand-assets.sh` |
| `icon-192.png`, `icon-512.png` | `assets/images/favicon.svg` | same |
| `og-image.jpg` (1200 × 630) | `_src/brand/og-image.html` | same |

If Chrome isn't found automatically, run `CHROME=/path/to/chrome bash _tools/render-brand-assets.sh`.

## Styling

`assets/css/styles.css` is a single documented file. Its table of contents is at the top.

- **Tokens:** type scale (fluid `clamp()`), spacing, radii and brand colours. Re-theme here first.
- **Theme colours:** semantic variables (`--surface`, `--text`, `--accent`, `--primary`…) are defined twice, for `:root` (light) and `[data-theme="dark"]`. Components use only these variables, so both themes follow automatically.
- **Breakpoints:**

  | Width | Changes |
  |---|---|
  | 1100px | Small laptop layout |
  | 960px | Tablet layout; the menu becomes a full-screen panel |
  | 720px | Phone layout; the quick-action bar appears at the bottom |
  | 520px | Small phone layout |

- **Conventions:**
  - Classes are short and component-based (`.svc`, `.biz`, `.fleet-card`).
  - States use `.is-*` classes.
  - **JavaScript never depends on classes**; it uses `data-*` hooks, so you can rename or restyle freely.

**Brand**

| Role | Colour |
|---|---|
| Primary: Deep Navy | `#0A2463` |
| Secondary: Bright Teal | `#247BA0` (darkened to `#1F6F92` for text, to meet AA contrast) |
| Accent: Warm Grey | `#E0E0E0` |
| Accent: White | `#FFFFFF` |

**Typography:** General Sans (Fontshare) for headings, Roboto for body text, Roboto Mono for booking numbers. To change fonts, edit `--font-display`, `--font-body` and `--font-mono`, and the font `<link>`s in `head()` in `build.py`.

## JavaScript architecture

The scripts load in this order (all `defer`):

1. **`config.js`** sets `window.SWIFTLINK`, the business data.
2. **`main.js`** provides the shared behaviour and exposes **`window.SL`**:
   `calc`, `money`, `rangeText`, `vehicle`, `isHoliday`, `fillRegions`, `fillRange`, `toast`, `post`, `track`, `validate`, `$`, `$$`.
3. **`quote.js`** and **`track.js`** load only on their own pages, through `script:` in the page header.

Each page module in `main.js` looks for its own `data-*` hook and exits if the page doesn't have it:

| Hook | Module | Page |
|---|---|---|
| `[data-console]` | `initConsole` | index |
| `[data-sg-map]` | `initMap` | index |
| `[data-faq-list]` | `initFaq` | index |
| `[data-fleet-grid]` | `initFleet` | services |
| `[data-matcher]` | `initMatcher` | services |
| `[data-rates-table]` | `initRates` | services |
| `[data-subnav]` | `initSubnav` | services |
| `[data-gallery]` | `initGallery` | gallery |
| `[data-contact-form]` | `initContact` | contact |
| `[data-legal-toc]` | `initLegalToc` | privacy, terms |

To add a feature:

1. Write an `initSomething()` that starts with `var el = $('[data-something]'); if (!el) return;`.
2. Call it from the `DOMContentLoaded` handler in `main.js`.

The code is plain ES5 for broad browser support.

## Accessibility

The template already includes:

- a skip link, landmarks and a breadcrumb on every interior page;
- labelled form fields with inline, announced errors (`aria-invalid`, `aria-live`);
- keyboard-operable tabs, map regions, steppers, FAQ and lightbox (arrow keys and Esc), with focus returned on close;
- visible focus styles;
- colour contrast tuned for WCAG AA in both themes;
- `prefers-reduced-motion` support, which turns off animations;
- 44 px minimum touch targets.

Keep the `aria-*` attributes when you edit components.

## Deployment

**Upload:**

- all `*.html` files in the project root;
- `assets/`;
- `sitemap.xml`, `robots.txt` and `site.webmanifest`.

**Do not upload** `_src/`, `_tools/` or `README.md`.

| Host | 404 page | Notes |
|---|---|---|
| Netlify, Vercel, Cloudflare Pages, GitHub Pages | Uses `404.html` automatically | Deploy the folder as-is (publish directory = project root) |
| Apache / cPanel | Add `ErrorDocument 404 /404.html` to `.htaccess` | – |
| Nginx | `error_page 404 /404.html;` | – |

If the site is served from a sub-folder, set `SITE["base_path"] = "/folder/"` and `SITE["url"]` accordingly, then rebuild.

## Re-using the template for another client

1. **Identity:** update `SITE`, `COMPANY` and `SOCIAL` in `build.py`, and `company` in `config.js`.
2. **Brand:**
   - colour tokens in `styles.css`;
   - the logo SVG (`LOGO` in `build.py`, `favicon.svg`, `_src/brand/*`);
   - fonts.
   Then run `render-brand-assets.sh`.
3. **Offer:** update services, vehicles, regions, prices, add-ons and surcharges in `config.js`. Keep the service blocks in `services.html` and the radios in quote step 1 in sync.
4. **Content:**
   - page copy in `_src/pages/`;
   - photos, then run `optimize-images.sh`;
   - FAQ, testimonials, careers and legal pages.
5. Rebuild, then run through the pre-launch checklist.

## Pre-launch checklist

**Business data (sample in the template)**

- [ ] Company name, UEN, LTA licence number, registered address, phone, emails (`build.py → COMPANY`, `config.js → company`)
- [ ] WhatsApp number: a **mobile** number with WhatsApp Business, not the landline
- [ ] All rates, minimums, surcharges, add-ons and the price spread (`config.js`) confirmed with operations
- [ ] "From S$…" prices typed in `index.html` and `services.html` match `config.js`
- [ ] Region response times and covering hubs (`config.js → regions`)
- [ ] Public holidays for the current and next year, checked against mom.gov.sg (`config.js → publicHolidays`)
- [ ] Dispatch hours (`config.js → dispatch`), and "24/7" claims in copy if the company isn't 24/7

**Content**

- [ ] Hero figures (12+ yrs, 15 min…), company story, milestones, team descriptions
- [ ] Testimonials: real, approved client feedback only (the template names are fictional)
- [ ] Careers: real openings, benefits and licence requirements
- [ ] Photos replaced with the company's own fleet, staff and premises; WebP regenerated
- [ ] Social profile URLs set, or `""` to hide them
- [ ] Google Maps link of the real premises (`contact.html`)

**Legal**

- [ ] Privacy policy and terms reviewed by the client's lawyer or DPO. Items marked `[confirm]` and `[sync]` in the page comments are resolved
- [ ] DPO contact email is monitored
- [ ] "Last updated" dates set

**Technical**

- [ ] `SITE["url"]` set to the live domain, then rebuilt (canonical URLs, sitemap, share previews)
- [ ] Form endpoints set (`config.js → forms`) and both forms tested end-to-end
- [ ] Tracking connected to the dispatch system (`track.js → lookup()`), or the Track page and console hidden until it is
- [ ] Demo numbers and the "Demo data" note removed
- [ ] GA4 ID set (optional), and privacy section 10 matches
- [ ] 404 page configured on the host
- [ ] `sitemap.xml` submitted in Google Search Console; Google Business Profile linked
- [ ] Share preview checked (e.g. LinkedIn Post Inspector, or by sending the link on WhatsApp)
- [ ] HTTPS enabled
